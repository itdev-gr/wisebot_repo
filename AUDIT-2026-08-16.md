# WiseBot — Full Audit, 16 Αυγούστου 2026

Covers application code, the Supabase database, deployment, content and operations.
Database findings come from the Supabase advisors plus a direct `pg_proc` privilege query,
not from reading migrations — they reflect what is live in production right now.

## ✅ P0 — FIXED 16 Αυγούστου 2026

Migration `revoke_public_execute_on_credit_functions` applied to `wisebot-academy`.
`anon` and `authenticated` no longer hold EXECUTE on `spend_credits`, `earn_credits`,
`transfer_credits`, `add_purchased_credits` or `cleanup_expired_otp`; `service_role` retains
it. Verified against `pg_proc` after applying. No deploy needed — the change is in the
database. No application change was required: all four callers are server-side endpoints
using `SUPABASE_SERVICE_KEY`.

The original finding is kept below for the record.

### DB-1: Anyone can mint credits without signing in

Four `SECURITY DEFINER` functions have `EXECUTE` granted to the **`anon`** role, so they are
callable over the public REST API with only the publishable anon key — which ships inside the
browser bundle, and the repository is public.

Verified directly:

| Function | anon EXECUTE | authenticated EXECUTE | SECURITY DEFINER |
|---|---|---|---|
| `add_purchased_credits(uuid, int, text)` | **yes** | yes | yes |
| `earn_credits(uuid, int, text, text)` | **yes** | yes | yes |
| `spend_credits(uuid, int, text)` | **yes** | yes | yes |
| `transfer_credits(uuid, uuid, int, text, text)` | **yes** | yes | yes |
| `handle_new_user()` | **yes** | yes | yes |
| `rls_auto_enable()` | **yes** | yes | yes |
| `claim_referral(...)` | no | no | yes |

Because the functions are `SECURITY DEFINER`, they bypass RLS entirely and accept the target
`user_id` as a **parameter** — the caller is never checked against it.

Consequences, all reachable by an unauthenticated stranger:

- **Mint unlimited credits** for any account via `add_purchased_credits` or `earn_credits`,
  destroying the paid economy the whole product rests on.
- **Drain another child's credits** via `spend_credits` with their user id.
- **Move credits between accounts** via `transfer_credits`.

`claim_referral` is correctly locked down (no EXECUTE for either role), which shows the right
pattern already exists in this project — it simply was not applied to the other four.

**Fix:** `REVOKE EXECUTE ... FROM anon, authenticated` on all six, leaving only `service_role`.
Every legitimate caller is a server-side endpoint under `api/` using the service key, so
nothing in the app should break. Verify `api/_lib/auth.ts` and the Stripe webhook use the
service role before revoking.

**Do this before anything else in this document.**

## 🟠 P1 — Correctness that touches money

### ✅ API3: Credit race conditions — STALE, not a real issue
`AUDIT-BUGS.md` still lists this as open. Reading the live function definitions shows it was
fixed at some point and the note was never updated. Every money path is race-safe:

- `spend_credits` — `SELECT … FOR UPDATE` before the balance check
- `earn_credits` — a single atomic `UPDATE … RETURNING`
- `transfer_credits` — locks **both** profile rows in deterministic id order, explicitly to
  avoid deadlocks between opposing transfers
- Stripe webhook — `purchases_stripe_session_id_key` UNIQUE constraint, with the insert
  itself used as the lock

Two narrower problems were found in the same pass, both now fixed:

### ✅ Paid purchase could silently grant no credits — FIXED
`api/stripe/webhook.ts`: if `earn_credits` failed *after* the purchase row was inserted, the
error was logged and `received: true` returned. Stripe never retried, the purchase row made
the session look processed forever, and the child never got what the parent paid for. The
handler now deletes the purchase row and returns HTTP 500 so Stripe redelivers.

### ✅ `add_purchased_credits` check-then-act race — FIXED
Migration `fix_add_purchased_credits_race_and_search_path`. It now takes `FOR UPDATE` on the
purchase row before checking status, and **refuses to grant credits when no purchase row
exists** — previously the `UPDATE` matched zero rows and it credited anyway. `search_path` is
pinned at the same time. Dead code today (no callers), fixed rather than dropped.

### H4: Free retries
"Try Again" re-enters a paid step without charging while the server bills every attempt.

### 13 remaining `react-hooks/exhaustive-deps`
All in games and secondary components (`MusicStudio`, `QuizEngine`, `BallRush`, `WizardDuel`,
`AdminDashboard`, `GiftModal`, `HeroSlingshot`, `SkyMetropolis`, `TacticalFootball`,
`WiseCards`). Worst case is a visual glitch, not a charge. The 9 in credit/auth paths were
fixed on 16 Αυγούστου (commit `e02bdba`).

## 🟠 P2 — The missing safety net

- **Zero tests.** 55,774 lines of TypeScript, 0 test files.
- **No CI.** No `.github/workflows`. Anything pushed to `main` deploys straight to
  `wisebot.gr`. The `workflow` token scope is now available, so this can finally be built.
- **`strict` is off** in `tsconfig.json`. `strictNullChecks` is the one that matters — bug `C1`
  was a production crash on `selectedHero.avatar.startsWith()`.
- **Lint: 48 errors, 601 warnings** (was 655 errors). The remaining errors are `prefer-const`,
  `ban-ts-comment`, `no-control-regex`, `no-empty` — none are hook rules.
- **8 components over 800 lines**, four over 1,200. This is where hook bugs cluster.

## 🟡 P3 — Database security hygiene

- **7 functions with mutable `search_path`**: `spend_credits`, `earn_credits`,
  `add_purchased_credits`, `transfer_credits`, `handle_new_user`, `sync_parent_verified`,
  `cleanup_expired_otp`. Fix with `SET search_path = public, pg_temp`.
- **Leaked-password protection disabled** in Supabase Auth. One dashboard toggle; checks new
  passwords against HaveIBeenPwned.
- **3 tables with RLS enabled but no policies**: `error_logs`, `ip_rate_limits`,
  `rate_limits`. This denies all access by default, so it is safe — but only intentional if
  every writer uses the service role. Confirm, then document.

## 🟡 P4 — Database performance

- **8 unindexed foreign keys**: `credit_transactions.user_id`, `gift_items.from_user_id`,
  `gift_items.to_user_id`, `heroes.user_id`, `profiles.referred_by`, `purchases.user_id`,
  `user_songs.user_id`, `user_videos.user_id`. These are the columns every per-user query
  filters on — the cheapest performance win available.
- **~20 RLS policies re-evaluate `auth.<fn>()` per row.** Wrap as `(select auth.uid())`.
- **`heroes` has two overlapping permissive SELECT policies** for every role.
- **2 unused indexes**: `ip_rate_limits_window_idx`, `idx_phone_verifications_phone`.
- **Auth connection strategy is absolute (10)** — scaling the instance will not help Auth
  until this becomes percentage-based.

## 🟢 Verified correct — do not "fix"

- **No AI key reaches the browser.** All Gemini calls go through `api/ai/*`; `vite.config.ts`
  deliberately blanks `API_KEY`/`GEMINI_API_KEY`. Client env exposes only `VITE_SENTRY_DSN`.
- **No secrets committed.** `.env` gitignored and untracked; no JWT literals in source.
- **Kid-safety moderation is real** — Greek *and* English blocklists plus Gemini
  `SAFETY_SETTINGS` at `BLOCK_LOW_AND_ABOVE`.
- **Admin auth is server-side**, 12h HMAC token, deliberate brute-force delay.
- **Security headers** set in `vercel.json`; **caching strategy** sound; **PWA** precaches only
  the app shell.
- **RLS policies exist and are per-user** on `profiles`, `heroes`, `stats`, `badges`,
  `purchases`, `credit_transactions`, `gift_items`, `user_videos`, `user_songs`.

## 🔧 Operations

- **The repository is public** (`itdev-gr/wisebot_repo`). No secrets are exposed, but the
  schema, RPC names and endpoint structure are readable by anyone — which materially raises
  the risk of DB-1 above.
- **Repo lives on the iCloud-synced Desktop.** Typecheck: 4.8s CPU spread over ~3 minutes
  wall clock. `git status` can hang past two minutes. Moving to `~/Projects/` fixes it, and
  is now safe because GitHub holds a verified copy.
- **`server/.env` is the only local copy** of `SUPABASE_SERVICE_KEY`, `STRIPE_SECRET_KEY`,
  `STRIPE_WEBHOOK_SECRET`, `GEMINI_API_KEY`. Gitignored, so `git push` does not protect it.
- **No Time Machine backup.** iCloud is sync, not backup — a deletion propagates.
- **Homebrew not installed** (needs a sudo password only the owner can type).
- **Vercel Node version is 24.x** for this project — not the one the dashboard warns about.

## Recommended order

1. **DB-1** — revoke the anon grants. Live, exploitable, unbounded financial loss.
2. **API3** — atomic credit deduction.
3. **CI** — typecheck + lint + build on push, so nothing broken reaches children again.
4. **8 unindexed foreign keys** — one migration, immediate speed-up.
5. **Tests for `EconomyContext`**, then `strictNullChecks`.
6. **Content**: the Γ' Δημοτικού sample unit, then the rest.
7. Cleanup: `search_path`, leaked-password protection, remaining hook fixes, dead endpoints.
